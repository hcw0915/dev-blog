> [Relo](https://getrelo.app) 是我一個人做的關係管理 App，程式幾乎都是 AI 寫的。這篇講的是：不寫程式之後，我在做什麼。

答案是兩件事：

- **Harness**：搭 AI 的外框。開工前一定會讀到的規則、做錯時會撞到的牆、讓它看到結果的回饋通道。
- **Loop**：設計工作循環。哪些步驟 AI 自己跑完，哪些一定停下來等我。

## Harness：擋 AI，還是讓 AI 看到結果

| 層 | 作用 | 性質 |
|---|---|---|
| 規則記憶 | 每條寫「規則／為什麼／怎麼套用」，每次對話自動載入 | 限制 |
| 職責 skill | 一個職責一份說明，跑過兩次的指令收成腳本 | 限制＋工具 |
| Hook | 工具呼叫前硬擋 | 硬限制 |
| MCP 連接器 | AI 自己查資料庫、部署、信件 | 回饋 |
| 排程 | 定時巡檢、週報 | 回饋 |
| 總帳與看板 | 結果登記、我直接在上面回覆決定 | 雙向 |

幾個取捨：

- **規則要附「為什麼」**。AI 碰到規則沒寫到的情況，才能從原因推回該怎麼做。
- **Hook 只有一支**：禁止 Android 的 `monkey` 隨機測試。hook 是字面比對、全有全無，只有「絕對不能發生、而且字面認得出來」的事才值得寫成牆。它擋得多徹底？整理素材時 AI 用 `cat` 讀這支 hook，指令裡有 `monkey`，自己被擋了下來。
- **權限刻意全開**。逐次按「允許」會讓人養成不看就按的習慣，等於沒把關。改用書面規則、hook，加上排程開頭的「唯讀」鐵則。
- **讓 AI 自己去看**。「遇到事情麻煩先看自己能不能做」—— 能用 CLI、API、MCP 查的，就不叫我截圖貼過去。

## Loop：哪裡自動，哪裡一定停

```
一句話或排程觸發 → 判斷：記錄還是開工？
→ 拆成互不重疊的任務，平行派 agent（各自一個 worktree）
→ 實作、自我驗證 → 回報並登記總帳
→ 整合分支跑全套測試 → 我決定 → 發布 → 發布後驗證
```

| 步驟 | 自動？ |
|---|---|
| 收到我的想法 | **停**，只記錄，等我說「做」 |
| bug、設計與文案選擇、實作、測試 | 自動，事後回報 |
| 資料庫 migration | 自動，但先過 staging |
| 發布、送審、對外發文 | **停** |
| 花錢、帳號安全、法務、產品方向 | **停** |

停的只有這五類，其他由 AI 決定，回報寫「我決定了 X，理由是 Y」。要我決定時，一張卡只問一件事，附選項和建議，累積起來一次問。

分工上，每個背景 agent 帶一個職責標籤（QA、SRE、發版工程師……），主對話只派工、看結果、回報。所有結果先登記進唯一的總帳，**總帳以外的事不算數** —— 這條規則來自我那句「每次都很多漏掉，很煩」。

## 回饋訊號：修 bug 之外，還要補訊號

Loop 能不能自己閉合，取決於 AI 有沒有辦法知道自己做對了。

有一次我回報「點進活動頁是整片藍色」。AI 在模擬器重現後找到根因：`useAnimatedStyle` 裡呼叫了沒有 `'worklet'` 標記的函式。Android 上動畫跑在 UI 執行緒，直接拋錯，整棵 React 樹被拆掉，只剩原生根畫面的品牌藍。網頁版動畫跑在 JS 執行緒，所以 web 測試全綠。

修法只補一個 `'worklet'`，但重點是後面補的兩個訊號：

- 一個 jest 測試：用 Reanimated 的 babel plugin 編譯所有檔案，worklet 呼叫到非 worklet 函式就失敗。
- 一個 e2e：CPU 降速加慢網路，4 秒內畫面要出現，而且**不能是單一顏色**。

修 bug 只修好這一次，補上訊號之後，同一類 bug 以後都會被自動抓到。其他同類的訊號還有：用 SQL 切換角色重播 App 的每個查詢，驗證資料庫權限沒改壞；交付畫面前自己截圖看過，「看不到就不能說做好」。

## 每條規則背後都是一次被糾正

| 失效 | 後來的規則 |
|---|---|
| 說「已上線」，正式環境其實缺欄位 | 說之前先查真實來源，否則標「未驗證」 |
| web 測試全綠，Android 實機壞掉 | 動畫與原生 UI 一定要上模擬器 |
| 隨口一句被當指令，開了三個 agent | 先記錄、不動作 |
| 一件事等我，全部停工 | 一件卡住不影響其他 |
| 每次檢查都冒出新問題 | 固定 9 個檢查面向 |
| 週報沿用過時結論 | 報告前查即時狀態 |

有一次 AI 先把每日備份上線了，但自己標出「這違反了 CI 只能手動觸發的規則，需要你同意」，我再追認。這比先問再做快，也比默默做掉安全。

## 結論

不寫程式之後，我的工作是：畫出 AI 該停的邊界，把每次糾正寫成附理由的規則，讓 AI 看得到自己的結果，讓我要做的決定好回答。

這套 harness 不是事先設計的，是一次一次被問題逼出來的。
